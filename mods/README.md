# agent-tooling plugin

The Claude Code plugin every session on this Mac loads from `~/agent-tooling/mods`: it redraws replies for skimming, turns a reply's decisions into the Reply band, and adds the prompt hint's thread state, the tab title and a notification when a turn ends done or asking you. `hooks/register.tsx` wires it; `charts/` hands a reply's Mermaid fences to Mermaid itself. What a reply should contain is `instructions/AGENTS.md` (Writing); this file is what the plugin draws from it.

## Features

The plugin adds two sections to the system prompt: one asking for those charts and alerts (`chart.tsx`, `SECTION`), and the one way to give the owner a button: every choice in a `🔴 Needs you` block with quoted replies, every message he sends to other people in a `draft` fence (`reply/band.tsx`, `BUTTONS`), which also says an open block stays in the band, so no reply repeats it unchanged.

Around the prompt:

| Feature | What it does | Code |
| --- | --- | --- |
| Reply band | The last reply's `🔴 Needs you:` decisions as rows above the prompt, numbered as the reply numbers them; in fullscreen, while that reply shows its whole block on screen, only the band's header line (its rows back once part of the block scrolls away; a draft's row likewise with its fence); only a reply the agent quotes and offers is a chip, so a decision without one is answered in words. Pressing a chip, in the band or in the reply, picks it (`[ ✓ reply ]`) and pressing it again takes it back; `★ all` picks the recommended reply of every unpicked decision; the pick that leaves no decision with chips unpicked sends them all as one prompt (`re 🔴1: a; 🔴2: b`), and `[ send n of m ]` sends what is picked so far. A grant (a reply with the word `go`, `Kei's go: …` too) sends on its own press like any reply (owner, 2026-10-27), but `★ all` never picks one, Tab's ghost text never offers one (it did: a grant recommended went out on Tab and Enter, 2026-10-28) and a prompt you type never carries one; a press that fills the prompt puts its answer before what you had typed, which stays. A page or link in a code span `! open <path or URL>` (http(s), or a local `.html`, `.pdf` or picture, a `#target` anchor kept by handing the page to the default browser) gets an `[ open ]` chip, in the reply and in its decision's row, which opens it in the default app. A press shows its effect on screen; only a copy, which shows none, and a press that failed say so in a toast. No chip has a hotkey. Your own prompt carries the picks before its text; Tab takes them, else the ★ replies, as ghost text; a chip of an earlier reply puts its answer, by its point, in the prompt. `dismiss` takes one row and its pick away, sending nothing; `explain` asks about one decision; typing `re:` offers the reply's lines to quote. After them a row per draft: its `copy` chip puts the draft on the clipboard as rich text (HTML, plain-text fallback, through `osascript`) and says so in a toast. A reply asking nothing leaves an unanswered band up, unless it says `Needs you: nothing.`; `hide`, ctrl+x ctrl+a, or your next prompt puts it away | `reply/` |
| Prompt hint | The thread's state, dim, after the hint under the prompt: `now: <step> 19m · done ~04:30Z · 1 for you` | `status.ts` |
| Reload | Once `update.sh` pulls newer plugin code, the session runs `/reload-plugins` itself when idle; `⟳ /reload-plugins` on the status line until it has | `status.ts` |
| Tab title | The session's name after the one glyph that says what it needs, most urgent first: `❌` the turn died on an API error (until the next turn), `🔴` a question the turn asked (AskUserQuestion) or a permission prompt (the main loop's or a subagent's, from the engine's PermissionRequest no hook decided until its call ends) waits on you, both ahead of `◐` since they stop the turn that works, `◐` the turn works, `🔴` the last reply's decisions wait on you, `◐` background work the session started (shells, agents, monitors, workflows, as the engine reports them when the main loop stops) runs on, `✓` the last reply says "You can close this session." (until the next turn); no glyph: nothing runs and nothing is asked (owner, 2026-10-28) | `status.ts` |
| Notification | When a turn ends in an interactive terminal tab and its reply asks something in a `🔴 Needs you` block, or opens `Done.` or `Not done:`, a desktop notification through Ghostty (OSC 777, one write between the engine's frames, as the tab title is): the session's name over `Needs you: <first ask>` or the verdict line, cut to 200 characters, `;` and control characters dropped. Ghostty is the one surface that notifies a Claude session: the Stop hook's osascript banner, which the owner never saw (owner, 2026-10-28), now posts for Codex only (`tools/status/notify_status.py`, which still writes `~/.runtime/needs` for `board --status`) | `status.ts` |
| Session file | The contract a host showing the sessions elsewhere reads (tools.ai-usage-menu's `ai-companion-host`, for the phone): `~/.runtime/claude-sessions/<sessionId>.json` (directory 700, file 600), for a session in a terminal tab, holding what only the plugin knows, `{"version": 1, "sessionId", "name", "glyph", "notice", "decisions": [{"n", "title", "text", "commands", "drafts", "options": [{"text", "recommended", "grant"}], "answered"}], "updatedAt"}`: `name` and `glyph` the tab title's (`glyph` one of `❌ 🔴 ◐ ✓` or `""`), `notice` the last turn's notification body (`""` while a turn works or when it notified nothing), `decisions` the Reply band's open ones (numbered as the reply numbers them, a dismissed row gone; `text` the whole item as written (Markdown kept, its `! cmd` lines out), `commands` those lines' commands, to copy, `drafts` the item's `draft` fences as the band copies them (each body as Markdown; a run of one-line fences that are its replies is none), `recommended` the ★, `grant` a `go` reply that only an explicit press may send; `answered` once the owner's reply to the block went), `updatedAt` UTC to the second, when the content last changed. The plugin is its one writer: each change replaces it whole by a rename (`hooks/save.sh`), so a reader never sees part of one; it is removed when the session ends (exit, `/clear`, `/resume` to another), but a killed process leaves its file, so a reader checks the session still runs (`~/.claude/sessions/<pid>.json` naming the `sessionId`). The rest of a reply (verdict, drafts outside the block, tables) is in the transcript. A field added to version 1 is additive: a reader ignores what it does not know | `session.ts`, `save.sh` |
| `/rename` offer | Once per session with a handoff, the prompt suggests `/rename <thread>` | `register.tsx` |

## Run

[setup.md](../setup.md) step 4 installs it as a directory marketplace, which Claude Code reads from this folder; a session loads it at start. A session reloads newer code itself (Reload, above); one started before that feature needs `/reload-plugins` typed once. The engine features it builds on: fullscreen (`/tui fullscreen`; the band's buttons need its mouse), ctrl+o (every shell call in full), kitty graphics (the pictures). A reply's pictures need Playwright's `chrome-headless-shell`, which `install.sh` installs (never Google Chrome.app), and run the Mermaid script vendored in `charts/vendor/`. Off fullscreen, a session started with `--resume` prints its transcript before the plugin loads, so what scrolls into scrollback keeps the engine's own drawing.

## Develop

Change it by pull request from a worktree (the root README). `claude --plugin-dir <worktree>/mods` runs a session with the worktree's plugin; `claude plugin validate mods` checks what the engine would refuse.

## Verify

- `claude plugin test mods`: the hooks under a mocked engine.
- `uv run --script mods/e2e/run.py [--out DIR]` (in `scripts/check.sh`): resumes a synthetic session (turns answered `Not done:` and `Running:`, two shell calls, then `e2e/reply.md`) in the real `claude` with this checkout's plugin, in its own temporary `CLAUDE_CONFIG_DIR`. At 60, 100 and 200 columns it checks on the screen each reply feature above but `Blocked:` and `Failed:`, the gantt's now line, Mermaid's refusal, tmux and a reply waiting for its pictures off fullscreen, the draft's frame and `[ copy ]` chip, a one-line draft's frame fitted to it, draft fences offering a decision's replies drawn as chips, a reply's chips in the reply, and the band's title alone while the reply shows its block, and the tab title's `🔴`; on a 42-row screen at 60 and 100 columns, the band's rows, chips, `explain` and draft row once a wheel scroll takes the block away; with kitty graphics, the pictures; off fullscreen, the band's hint and rows; then that a click on a band chip picks its reply and a click on the same decision's other chip in the reply picks that instead, neither sending while a decision is open, and one click on `hide` puts the band away across a redraw; that the pointer on a chip's bracket lights its label too (a draft's `copy`, a reply's chip in the reply, a band chip) and leaving restores it; that the prompt's ghost text, the answer Tab takes from it and `★ all` leave a recommended grant out, sending nothing while it stays open; all in the light theme. Not covered: a pick that sends, `send`, `dismiss`, the dark theme, pressing `copy` (it would write the real clipboard; the unit tests check its command), what `explain` sends, `re:`, the prompt hint, Reload, the tab title's other glyphs, the notification and the session file (they follow turns), the `/rename` offer, `/resume` within a session. It never sends a prompt to a model. `--out` keeps each screen as text and PNG.
- A new feature gets its row here, a line in `e2e/reply.md` and a check in `e2e/checks.py` (on the final screen) or `e2e/acts.py` (after a click, scroll or key).

## Linux (Kei's port, 2026-10-28)

Runs on Kei's Linux desktop (Ghostty) and on vvs-box (ssh → herdr → tmux). What differs from the Mac:

| Feature | Linux |
| --- | --- |
| Tab title, session file | The engine's terminal is found as `pts/N`; TIOCOUTQ is Linux's `0x5411` |
| Draft `copy` | The draft verbatim (Slack markup kept) through the engine's own copy: wl-copy/xclip, else OSC 52, which reaches the desktop over ssh and tmux |
| `[ open ]` | `xdg-open` where there is a desktop; on the box a toast says there is none |
| Charts | `~/.cache/ms-playwright`, Chromium run with `--no-sandbox` (Ubuntu's AppArmor kills its sandbox); a theme with `dark` in its name (`custom:kei-dark-1`) draws the dark palette; in tmux (the box) the fence stays text |
| Notification | Off unless `AGENT_TOOLING_NOTIFY=1` (Kei, 2026-10-28) |
| Prompt hint | Needs Wendelin's `~/agent-tooling` progress library; without it the hint stays empty and nothing is polled |
| Verdict | May follow Kei's TL;DR mark: `🩷 **TL;DR:** (Needs You) Not done: …`, the mark drawn as written |
| Phone | claude-herd reads the session file and shows the open decisions in Vanna with a button per reply (`decisions.py`, `POST /api/chat/<pane>/answer`) |

Install: `claude plugin marketplace add <this folder>` then `claude plugin install agent-tooling@agent-tooling`; charts need `uv` and `uvx playwright install chromium-headless-shell`.
